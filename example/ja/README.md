# プロンプトとレポートの例

[リポジトリガイド](../../README_ja.md) | [English](../en/README.md)

目的に近い例を選び、対象、目標、根拠を自分の環境の観測結果に置き換えてください。各ページにプロンプト、レポート例、次に確認する項目を記載しています。

| 例 | 使用するskill | レポートで示すこと |
| --- | --- | --- |
| [01 — 遅いクエリ](01-slow-query.md) | 性能診断 | 行数推定の誤差、索引の仮説、原因を確定する前の確認 |
| [02 — ロック競合](02-lock-contention.md) | 性能診断 | 待機連鎖と、activityの可視性不足による判断の限界 |
| [03 — 設定レビュー](03-configuration-review.md) | 設定、性能診断 | 要求checkpoint、JIT時間の集計、対象を限定した比較 |
| [04 — テーブル設計](04-schema-review.md) | テーブル設計レビュー | 制約漏れ、命名、ライフサイクル、競合の根拠と妥当な例外 |
| [05 — セキュリティ](05-security-review.md) | セキュリティレビュー | ロール権限、RLSの経路、パスワードの未確認事項、TLSの実効アクセス |
| [06 — アップグレード準備](06-upgrade-readiness.md) | セキュリティレビュー、負荷検証 | upstreamとベンダーの根拠、更新状況の判定不能、書き込み後の復旧 |
| [07 — 負荷検証](07-workload-validation.md) | 負荷検証 | 応答時間が短くても、欠測があっても、結果不一致を問題として扱う判断 |

## 例の使い方

01〜06は仮想の観測値に基づくエージェントの回答例です。ファイル名は利用者が用意する根拠の置き場所を示します。同梱の入力データ、固定の出力テンプレート、本番環境で実測した改善ではありません。

07には[inputs/workload](../inputs/workload/)の小さなJSONファイル2つと、リポジトリのルートから実行するコマンドがあります。掲載した出力の抜粋は実際のスクリプトと照合しています。データは合成であり、性能の採用判断には不十分です。

呼び出しは`$skill-name`の形式です。利用するエージェントに合わせて構文を調整してください。プロンプトで指定したファイルを実際に渡すか、提供する観測結果に合わせてファイル名を変更します。確認済みの事実、不足情報、許可された変更範囲を明示し、欠測を架空の計測値で埋めないでください。

各ページ末尾のskillへのリンクから、全体の手順と参照資料を確認できます。これらの詳細資料は現在、主に日本語です。
